# background and timeline

## background

REA (Reversa Engineer Anything) is a tool designed to make reversa engineering easier to use with coding agents. Reverse 
engineering is the process of understanding how software works by examining the program itself. With REA, a coding agent can inspect a program or webpage, follow its code, and use information such as code references and runtime observations to explain how a specific feature works.
The main idea behind REA is to connect coding agents with tools that can investigate software in more detail.This allows a user to ask questions about how a feature works and use the collected evidence to understand or potentially rebuild that feature.

## Timeline

- **Early development:** The project originally exicted before the REA name and was developed around tools for binary analysis.

- **July 12, 2026:** Version 0.2.0 introduced an important change in the project's identity by renaming the package and command-line interface to REA. This release also added guided local onboarding and dynamic binary lifecycle features.

- **July 12, 2026:** Version 0.3.0 continued the development of the REA analysis platform. It added evidence-backed process investigations and typed analysis tools.

- **October 9, 2026:** REA version 6.3.0 was released with updates to areas such as JavaScript analysis , browser analysis, native analysis and evidence handling.

- **October 11, 2026:** Version 6.4.0 expanded the project further with Android device inspection, additional Ghidra capabilities , improvements for JavaScript analysis and support for larger analysis.

- **October 13, 2026:** Version 6.5.0 added further capabilities for JavaScript analysis and included analysis workflows involving managed assemblies, Android, WebAssembly, network data and other software artifacts.
